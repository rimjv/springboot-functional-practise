# Task Manager REST API

A practice REST API built with **Spring Boot** and **Java** to learn how backend services work: controllers, repositories, databases, validation, and testing. The API manages a simple to-do list (tasks) and supports full CRUD operations.

## Tech Stack

- Java 17+
- Spring Boot
- Spring Web (REST endpoints)
- Spring Data JPA (Hibernate)
- H2 in-memory database
- Gradle

## Getting Started

### Prerequisites

- JDK 17 or newer
- Git
- IntelliJ IDEA (optional, any IDE works)

### Clone the repository

```
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>
```

### Run the application

Windows (PowerShell):

```
.\gradlew.bat bootRun
```

Mac/Linux:

```
./gradlew bootRun
```

You can also run the main class (`DemoApplication`) from your IDE. The server starts on `http://localhost:8080` once you see `Started DemoApplication` in the console.

### Run the tests

Windows (PowerShell):

```
.\gradlew.bat test
```

Mac/Linux:

```
./gradlew test
```

## API Endpoints

### Health

| Method | Endpoint  | Description  | Success status |
|--------|-----------|--------------|----------------|
| GET    | `/health` | Health check | 200 OK         |

### Tasks

| Method | Endpoint      | Description        | Success status | Error status                |
|--------|---------------|--------------------|----------------|-----------------------------|
| GET    | `/tasks`      | List all tasks     | 200 OK         |                             |
| GET    | `/tasks/{id}` | Get a task by ID   | 200 OK         | 404 if the task is not found |
| POST   | `/tasks`      | Create a new task  | 201 Created    |                             |
| PUT    | `/tasks/{id}` | Update a task      | 200 OK         | 404 if the task is not found |
| DELETE | `/tasks/{id}` | Delete a task      | 204 No Content | 404 if the task is not found |

### Task object

```json
{
  "id": 1,
  "title": "Learn Spring Boot",
  "description": "Build a REST API step by step",
  "status": "TODO"
}
```

| Field         | Type   | Notes                                           |
|---------------|--------|-------------------------------------------------|
| `id`          | Long   | Generated by the database. Do not send on POST. |
| `title`       | String | Short name of the task                          |
| `description` | String | Optional details                                |
| `status`      | String | For example `TODO`, `IN_PROGRESS`, `DONE`      |

## Testing the API

Start the app first, then open a **second** terminal so the app keeps running. The examples below use PowerShell with `curl.exe`. Use `curl.exe` and not `curl`, because plain `curl` in PowerShell is an alias for a different command.

### 1. Create a task (POST)

```
curl.exe -i -X POST http://localhost:8080/tasks -H "Content-Type: application/json" -d "{\"title\":\"Learn Spring\",\"description\":\"Build a REST API\",\"status\":\"TODO\"}"
```

Expected: `201` and the saved task with its generated `id`.

### 2. List all tasks (GET)

```
curl.exe http://localhost:8080/tasks
```

Expected: `200` and a JSON array of tasks. The list is empty (`[]`) on a fresh start.

### 3. Get one task (GET by id)

```
curl.exe -i http://localhost:8080/tasks/1
```

Expected: `200` and the task with id 1.

### 4. Update a task (PUT)

```
curl.exe -i -X PUT http://localhost:8080/tasks/1 -H "Content-Type: application/json" -d "{\"title\":\"Learn Spring Boot\",\"description\":\"Updated\",\"status\":\"IN_PROGRESS\"}"
```

Expected: `200` and the task with the new values. PUT replaces title, description, and status.

### 5. Delete a task (DELETE)

```
curl.exe -i -X DELETE http://localhost:8080/tasks/1
```

Expected: `204` with no response body. A following `GET /tasks/1` returns `404`.

### 6. Task not found

```
curl.exe -i http://localhost:8080/tasks/999
```

Expected: `404 Not Found`. At this stage the response body is empty. A structured JSON error response is planned with global exception handling.

### Alternative: PowerShell's built-in commands

These avoid the quote escaping that `curl.exe` needs:

```
Invoke-RestMethod -Method Post -Uri http://localhost:8080/tasks -ContentType "application/json" -Body '{"title":"Learn Spring","description":"Build a REST API","status":"TODO"}'
Invoke-RestMethod -Uri http://localhost:8080/tasks
Invoke-RestMethod -Method Delete -Uri http://localhost:8080/tasks/1
```

### Alternative: Postman

1. Create a new request, pick the method, and enter the URL (for example `http://localhost:8080/tasks`).
2. For POST and PUT, open the **Body** tab, choose **raw**, set the type to **JSON**, and paste the task JSON.
3. Click **Send** and check the status code and response body.

### Suggested test sequence

1. `GET /tasks` returns `[]`.
2. `POST /tasks` two or three times (ids 1, 2, 3).
3. `GET /tasks` lists them all.
4. `GET /tasks/1` returns one task.
5. `PUT /tasks/1` changes its values, then `GET /tasks/1` confirms the change.
6. `DELETE /tasks/1`, then `GET /tasks/1` returns `404`.

### Common problems

| Symptom                     | Likely cause                                                        |
|-----------------------------|---------------------------------------------------------------------|
| Unable to connect           | The app is not running, or it is on a different port                |
| 404 on every URL            | A controller is outside the main class's package or sub-packages    |
| 415 Unsupported Media Type  | The `Content-Type: application/json` header is missing              |
| 400 Bad Request             | The JSON is malformed (often a quote escaping issue in PowerShell)  |
| Port 8080 already in use    | Another instance is running. Stop it, or set `server.port=8081`     |

## Viewing the database (H2 console)

To inspect the data directly, add this to `src/main/resources/application.properties`:

```properties
spring.h2.console.enabled=true
spring.datasource.url=jdbc:h2:mem:taskdb
```

Restart the app and open `http://localhost:8080/h2-console`. Use JDBC URL `jdbc:h2:mem:taskdb`, username `sa`, and an empty password. Then run:

```sql
SELECT * FROM task;
```

## How a request flows

```
Client (browser / Postman / curl)
        |  HTTP request, for example GET /tasks/1
        v
TaskController   receives the request and returns the response
        |
        v
TaskRepository   reads and writes the database (implementation generated by Spring)
        |
        v
Task (entity)    one row in the task table
```

## Key Concepts

### Why is there a HealthController?

`HealthController` is a simple "are you alive?" check. It has no database or business logic behind it. It just returns `{"status": "ok"}` when you call `GET /health`.

It is useful because:
- It confirms the app started and the web layer is working, before any real features exist.
- Monitoring tools, load balancers, and deployment platforms (Docker, Kubernetes, cloud services) commonly call a health endpoint to check whether a service is running.
- It is the smallest possible example of a controller, so it is a good first test of the setup.

### Why is there a DemoApplication.java?

`DemoApplication.java` is the **application entry point**. It holds the `main` method, which is where Java starts running the program.

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

When it runs, Spring Boot:
1. Starts an embedded web server (Tomcat) on port 8080.
2. Creates the Spring application context, which holds all the app's components.
3. Scans this class's package and its sub-packages for controllers, services, and repositories.
4. Applies auto-configuration based on the dependencies on the classpath, such as the database and JPA.

Every Spring Boot application has one such class, annotated with `@SpringBootApplication` and containing a `main` method. Its name can be anything, and `<ProjectName>Application` is just the convention.

### The Task entity annotations

- `@Entity` marks the class as a database table. Each `Task` object is one row.
- `@Id` marks the primary key column.
- `@GeneratedValue(strategy = GenerationType.IDENTITY)` lets the database auto-increment the id.
- A no-argument constructor is required so Hibernate and Jackson can create an empty `Task` and fill in its fields.
- Getters and setters let Jackson convert between JSON and objects, and let Hibernate read and write the fields.

### Dependency injection in TaskController

`TaskController` needs a `TaskRepository` to talk to the database. It declares that need as a constructor parameter, and Spring supplies the repository automatically. The controller never creates it with `new`.

```java
private final TaskRepository taskRepository;

public TaskController(TaskRepository taskRepository) {
    this.taskRepository = taskRepository;
}
```

### HTTP status codes used

| Code | Meaning    | Used for                                  |
|------|------------|-------------------------------------------|
| 200  | OK         | Successful GET and PUT                    |
| 201  | Created    | Successful POST (a new task was created)  |
| 204  | No Content | Successful DELETE (nothing to return)     |
| 404  | Not Found  | The requested task id does not exist      |

### Optional and ResponseEntity

`taskRepository.findById(id)` returns an `Optional<Task>`, which either holds a task or is empty. The controller maps a found task to a `200` response and an empty result to a `404`:

```java
return taskRepository.findById(id)
        .map(ResponseEntity::ok)
        .orElse(ResponseEntity.notFound().build());
```

### Why PUT loads the existing task first

In `PUT /tasks/{id}`, the app loads the task already stored in the database, copies the new values onto it, and saves it. The loaded task already has its `id`, so `save()` performs an update. Saving the incoming object directly would have a null `id` and insert a duplicate row.

### PUT, POST, and idempotency

- `GET`, `PUT`, and `DELETE` are idempotent: repeating the same request leaves the system in the same final state.
- `POST` is not idempotent: sending it twice creates two tasks.
